## 2. GitHub Release（v1.0.0）

**Tag**：`v1.0.0`
**Title**：`DualTorch 1.0.0 — 双灯常亮 + 真实档位调光`

**正文**

```markdown
第一个公开版本。

## 它能做什么

- **双灯常亮**：系统手电只点主摄那一颗，DualTorch 用相机会话把两颗一起点亮
- **单灯调光**：广角档走系统手电，档位直接对应 HAL 的 strength level，不做百分比糊弄
- **档位对齐硬件**：硬件有几档就生成几格，自动剔除 HAL 不认的最高档
- **控制中心磁贴**：一键开/关双灯，或在广角/双灯之间切换
- **常驻不灭**：前台服务持有灯光，退出界面、锁屏都不影响

## 安装

1. 下载 `DualTorch-v1.0.0.apk`
2. 允许安装未知来源应用
3. 首次打开授予相机权限与通知权限

要求 Android 10（API 29）及以上。

## 兼容性

在 **vivo X300 Ultra（V2547A）** 上完整实测。其它 vivo 双 LED 机型双灯大概率可用，档位数量需自测；其它品牌只保证单灯通路。

## 说明

- 无 `INTERNET` 权限，不联网、不收集数据
- 使用项目测试签名，仅供自用与测试
- 双灯满功率发热明显，请勿直射眼睛

完整说明见 [README](../README.md)。
```

## 6. V2EX / 知乎 / 少数派（长文）

**标题**

```
我给 vivo 双 LED 手机做了个「双灯手电」：绕过系统手电的单灯限制
```

**正文**

```
先说背景。vivo X300 Ultra 背面有两颗闪光灯，但系统手电永远只点亮主摄那一颗，另一颗只在拍照时参与。厂商没有开放「两颗一起常亮」的接口，`CameraManager.setTorchMode()` 拿到的也只是同一颗。

我试过几条路：

1. **系统手电 + 强度档位**：`turnOnTorchWithStrengthLevel()` 只能改电流，改不了灯数。
2. **逐个 cameraId 点灯**：这台机器只有主摄上报了 `FLASH_INFO_AVAILABLE`，长焦相机没有独立闪光灯单元。
3. **相机会话**：这条路通了。主摄会话把 `CONTROL_ZOOM_RATIO` 拉到 2× 及以上时，HAL 会按焦段同时驱动两颗 LED；再用 `setFlashOn(true)` 让它常亮。

最终做出来的东西叫 DualTorch，功能很克制：

- 双灯 / 广角两档灯路
- 广角档支持硬件档位调光，档位直接就是 HAL 的 level，不做百分比换算
- 控制中心两个磁贴、通知栏快捷操作
- 前台服务持有灯光，退出界面不灭
- 零网络权限

过程中有两个坑值得记一下：

**坑一：HAL 会静默忽略升档。** 灯已经亮着时，请求更高档位不一定生效，但也不报错。表现就是滑到最右，界面显示「最亮」，实际亮度还停在二档。解决办法是设档后立刻 `getTorchStrengthLevel()` 回读，不符就关灯重开一次。代价是偶尔闪一下，但档位是真的。

**坑二：声明的档位不等于可用档位。** 这台机器上报 5 档，但 torch 通路不接受最后一档，请求它会落回二档亮度。所以有效上限取「声明值 − 1」，默认停在第四档。

代码不依赖 Gradle，一个 `build-apk.sh` 走完 `aapt2 → javac → d8 → zipalign → apksigner`，方便改。MIT 协议。

需要说明的是：**只在 V2547A 上完整实测**。其它 vivo 双 LED 机型大概率能用同一套逻辑，但档位数量要自己试；其它品牌取决于 HAL 是否按焦段驱动双灯。装上先切「双灯」看两颗亮不亮，不亮就是不支持，单灯功能不受影响。

仓库：<你的 GitHub 地址>
```

## 8. Reddit / XDA（英文）

**Title**

```
DualTorch — turn on both LEDs of a dual-flash vivo phone (no root)
```

**Body**

```
Most dual-LED phones only light the main LED when you toggle the torch. The second LED is reserved for still capture.

On vivo devices, the camera HAL drives both LEDs when a capture session is zoomed to 2× or beyond. DualTorch opens a Camera2 session, sets `CONTROL_ZOOM_RATIO >= 2.0`, and keeps the flash on.

Features:
- Dual-LED constant torch
- Single-LED mode with real hardware strength levels
- Quick Settings tiles
- Foreground service, survives screen-off
- No INTERNET permission, no analytics

Two gotchas I hit:
1. The HAL silently ignores strength increases while the torch is on. The app reads back `getTorchStrengthLevel()` and power-cycles the torch if the value doesn't match.
2. The declared max level isn't always usable — this device reports 5, but the torch path rejects the last one and falls back to level 2. Effective max is `declared - 1`.

Calibrated on vivo X300 Ultra (V2547A). Other vivo dual-LED models may work; other brands depend on whether their HAL drives both LEDs by focal length.

MIT, no Gradle required. Repo: <your GitHub URL>
```
